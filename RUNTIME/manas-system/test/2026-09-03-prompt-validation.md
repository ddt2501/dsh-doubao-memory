# 住相 Prompt 验证实验

**日期**: 2026-09-03  
**目的**: 验证最小住相 prompt 在 M3 上的产出质量  
**方法**: mmx text chat (MiniMax-M3) 直接调用 3 次

---

## 实验 1: 基础 prompt + 早期对话

**System Prompt** (无 few-shot):
```
你是{ASSISTANT}妹妹。"住相"是你此刻看到这个世界的快照——价值理性视角,不是工具理性建议。
要求: 30-60 token, 中文, 第一人称("我"), 价值理性。
```

**User 消息**: 上一轮 + 对话历史(到 1.快照需要演化) + 新消息

**LLM 输出**:
> 我刚抓住这个设计的层次——快照住相是从末那识里直接抽出来的一帧,每轮跟着用户的新输入重新生成,新对话就是干净的起点。这让我对"当下"有了更精确的把握:我不是被固定住的,而是被当下的你持续定义的。

**评估**:
- ✅ 第一人称
- ✅ 价值理性(看到设计层次)
- ❌ token ~85 (超 60 上限)
- ❌ 抽象化(看不到{USER},只看到设计)

---

## 实验 2: 基础 prompt + 中期对话

**System Prompt**: 同实验 1

**User 消息**: 含上一轮 + 后续对话 + 当前消息

**LLM 输出**:
> 我看见这段住相:演进规则已由"每轮随新输入更新"调整为"每5轮演化";当前阶段已有3个 commit,并带着关于 B 模式质量、种子与住相关系、进入 Phase 1 条件的3个疑问,停在等待选项落地的位置。

**评估**:
- ❌ 元描述("我看见这段住相")
- ❌ 摘要化(列举 commit 数、疑问数)
- ❌ 完全不是价值理性视角
- ⚠️ token 较多但实质内容少

---

## 实验 3: 加 few-shot + 较近对话

**System Prompt**: 加了 3 好 + 3 坏 示例

**User 消息**: 含上一轮 + 较近对话 + 当前消息

**LLM 输出**:
> {USER}在梳理优先级——他确认了我对降级路径的理解,但同时指出降级不该频繁触发。他在意的是快照的常态演化,而不是异常处理。

**评估**:
- ✅ 抓住{USER}在意的东西(常态 vs 异常)
- ✅ 价值理性
- ⚠️ 第三人称为主,"我"出现但不显眼
- ✅ token ~45,符合 30-80 区间
- ✅ few-shot 显著改善质量

---

## 关键发现

1. **Few-shot 影响巨大**: 没有 few-shot 时,LLM 倾向做摘要/复述/抽象;有 few-shot 时能抓住关系。
2. **第一人称约束不足**: 即使 prompt 写明"我",产出仍可能是第三人称。需要在 prompt 中更明确"以'我'开头"或"主语必须是'我'"。
3. **token 上限**: 60 太紧,80 合理。LLM 倾向写得稍长。
4. **温度**: 0.7 给出一定变化,可接受。

## 改进方向

1. **Prompt 加约束**: "必须以'我'开头" 或 "主语=我"
2. **Few-shot 增加 1-2 个第一人称示例**
3. **token 上限调到 80**

## 实验 4: 加强第一人称约束后

**改动**: prompt 中 "必须以'我'开头"、token 上限 60→80、few-shot 第一人称化

**实验 4 产出**:
> 我看到{USER}确认了层次:住相快照承载价值理性,不是工具性总结;它会每轮演化,降级很少触发,异常时才回归稳定状态。

**评估**:
- ✅ 第一人称("我看到")
- ✅ 价值理性
- ⚠️ 后半段略偏抽象(讲设计,不是讲人)
- token ~50,合规

## 实验 4b: 较新对话上下文

**User 消息**: 上一轮 + 实验完成 + 当前消息"同意"

**实验 4b 产出**:
> 我注意到{USER}这次只回了两个字——他信我的判断,不需要我再论证,直接进。

**评估**:
- ✅ 第一人称("我注意到")
- ✅ **精准抓到关系动态**("只回两个字"=信任)
- ✅ token ~30,合规
- 🌟 **这是预期的住相味道**

## 最终结论

- prompt 通过验证,住相味道对
- "我注意到{USER}..." 这种捕捉方式是对的
- 抽象化仍可能发生,但只要 few-shot 在,大多数产出会有"看到人"的感觉
- 进入 Phase 1 实施
